# Job Research

پایهٔ برنامهٔ جستجوی شغل برای نقش‌های فنی Senior DevOps، Platform و SRE با هدف ریلوکیشن.

## وضعیت فعلی

این نسخه اتصال قابل تنظیم به مدل، وایت‌لیست منابع، فیلتر اولیه، ارکستریتور،
ثبت وضعیت در SQLite و تولید پیش‌نویس از ورودی JSON را پیاده می‌کند.
جستجوی اینترنتی و جمع‌آوری اولیه با Brave اضافه شده است؛ کلید سرویس لازم است.
اجرای ساعتی و ارسال ایمیل هنوز پیاده نشده‌اند.
هیچ رزومه یا اطلاعات محرمانه‌ای در مخزن قرار ندارد.

## اجرا

Python 3.10+؛ این مرحله وابستگی خارجی ندارد.

```bash
cp .env.example .env
python model_client.py --profile data/profile.json --job data/job.txt
```

پوشهٔ data را بسازید؛ profile.json شامل اطلاعات واقعی و تأییدشدهٔ رزومه و
job.txt متن آگهی باشد. خروجی، JSON دارای subject و body است و ایمیلی ارسال نمی‌شود.

## اتصال به مدل

LLM_BASE_URL آدرس پایهٔ سرویس شامل مسیر /v1 است؛ IP، پورت و مسیر
همگی قابل تغییرند. LLM_MODEL نام دقیق مدل ارائه‌شده در سرویس است.
LLM_API_KEY برای سرویس‌هایی که احراز هویت دارند تنظیم می‌شود.

برای vLLM آدرس سرویس خودتان را وارد کنید.
برای OpenRouter آدرس پایه https://openrouter.ai/api/v1 است؛ کلید و شناسهٔ
مدل باید متعلق به همان سرویس باشند. برای سایر سرویس‌ها نیز API سازگار
با Chat Completions لازم است. تغییر سرویس صرفاً با تغییر تنظیمات انجام می‌شود.
سرویس‌های دارای پروتکل متفاوت به adapter جدا نیاز دارند.

خطا، پاسخ ناقص و JSON نامعتبر به‌عنوان شکست گزارش می‌شود؛ تغییر خودکار به
سرویس پولی وجود ندارد. بررسی انسانی متن پیش از استفاده، برای اطمینان از
درستی سوابق لازم است؛ این مرحله فقط تولید پیش‌نویس است.

## مراحل بعدی

- منابع مجاز جستجو و استخراج آگهی، با ثبت لینک و تاریخ.
- فیلتر عنوان فنی، کشور و زبان انگلیسی؛ حقوق قابل مذاکره.
- بررسی جداگانهٔ شواهد حمایت از ویزا و کمک ریلوکیشن؛ موارد مبهم برای بررسی.
- ثبت پایدار آگهی، صف و سابقهٔ درخواست برای جلوگیری از ارسال تکراری.
- اجرای ساعتی و سقف قابل تنظیم؛ مقدار پیشنهادی اولیه پنج ارسال در روز.
- ارسال با ایمیل استخدامی مستند یا مسیر رسمی درخواست؛ بدون حدس آدرس ایمیل.

مقادیر SEARCH_INTERVAL_SECONDS، DAILY_EMAIL_LIMIT و SEND_EMAILS در نمونهٔ
تنظیمات برای مراحل بعدی رزرو شده‌اند و در نسخهٔ فعلی اثری ندارند.

## ساختار ماژول‌ها

- app/settings.py: تنظیمات اتصال به مدل.
- app/sources.py: خواندن و اعتبارسنجی وایت‌لیست.
- app/intake.py: دریافت آگهی‌های نرمال‌شده از JSON.
- app/filtering.py: فیلتر اولیه و ارجاع شرایط مبهم به بررسی.
- app/llm.py: تولید پیش‌نویس با مدل انتخابی.
- app/storage.py: ثبت پایدار وضعیت و پیش‌نویس در SQLite.
- app/orchestrator.py: هماهنگی مراحل و سقف پیش‌نویس در هر اجرا.
- run_pipeline.py: نقطهٔ ورود خط لوله.
- config/sources.json: منابع و کشورهای هدف، قابل ویرایش.
- config/README.md: راهنمای افزودن سایت و سیاست مخاطب استخدام.

ارکستریتور فعلی یک خط لولهٔ قطعی پایتونی است؛ CrewAI هنوز وابستگی پروژه نیست.
بخش دریافت آگهی بعداً می‌تواند adapter یا Flow مربوط به CrewAI را فراخوانی کند.

### اجرای ارکستریتور

```bash
python source_config.py
python run_pipeline.py --jobs data/jobs.json --profile data/profile.json
```

jobs.json آرایه‌ای از اشیاء شامل url، title، country، description،
english_working_language و وضعیت مستقل visa_sponsorship و relocation_support است.
برای هر وضعیت مثبت، فیلد متناظر با پسوند _evidence شامل quote و url لازم است.
این مرحله صحت ادعای مدرک را از اینترنت بازخوانی نمی‌کند؛ ورودی باید قبلاً بررسی
شده باشد. شروط مبهم review، خطای مدل pending و خروجی موفق drafted ثبت می‌شود.
موارد پردازش‌شده دوباره تولید نمی‌شوند. برای بازبینی تغییر آگهی، مدیریت نسخهٔ
آگهی و رابط بازگرداندن وضعیت هنوز نیاز به پیاده‌سازی دارد.

سقف پیش‌نویس --draft-limit فقط برای همان اجراست و سقف ارسال روزانه نیست.
قفل چند worker، کنترل روزانه و ارسال ایمیل در این مرحله پیاده نشده‌اند.

## جستجوی اینترنتی و صف بررسی

```bash
python discover_jobs.py
python -m unittest discover -s tests -v
```

در .env مقدار BRAVE_SEARCH_API_KEY را تنظیم کنید. استفاده از سرویس جستجو
تابع حساب و هزینهٔ همان سرویس است؛ این برنامه کلید یا اشتراک تهیه نمی‌کند.
SEARCH_PROVIDER فعلاً brave است؛ adapter جستجو از سایر مراحل جداست.
SEARCH_MAX_QUERIES_PER_RUN و SEARCH_MAX_PAGES_PER_RUN مصرف هر اجرا را محدود می‌کنند.

برنامه برای هر منبع فعال، یک جستجوی محدود به دامنه با عنوان‌های فنی و عبارت‌های
visa/relocation می‌فرستد. سپس نتایج مجاز را می‌خواند. تمام مقصدهای redirect
پیش از دنبال شدن با وایت‌لیست مقایسه می‌شوند. اگر اطلاعات schema.org
JobPosting در HTML موجود باشد، عنوان، شرکت، کشور و شرح شغل استخراج می‌شود؛
سایر صفحه‌ها با برچسب unverified_page_candidate ذخیره می‌شوند و ممکن است
صفحهٔ فهرست باشند، نه یک آگهی واقعی. صفحات نیازمند JavaScript یا ورود
هنوز adapter مرورگر ندارند؛ دامنهٔ مجاز لزوماً به معنی پشتیبانی کامل سایت نیست.

همهٔ خروجی‌ها با وضعیت review در SQLite قرار می‌گیرند؛ وایت‌لیست، فهرست
دامنه‌های مجاز است و صف review، فهرست آگهی‌های نیازمند بررسی.
برنامه از روی وجود کلمهٔ visa یا relocation در نتیجهٔ جستجو، حمایت را
تأیید نمی‌کند و هیچ ایمیلی ارسال نمی‌شود. ادعای تناسب با رزومه نیز در مرحلهٔ
کشف صادر نمی‌شود. data/discovered_jobs.json فقط خروجی جدید همان اجراست.
موارد قبلی در دیتابیس می‌مانند؛ رابط تأیید و بازگرداندن review به pending
در مرحلهٔ بعد لازم است.

این مرحله با ابزار جستجو و استخراج قطعی پیاده شده، نه CrewAI.
CrewAI می‌تواند بعداً همین adapterها را به‌عنوان ابزار استفاده کند.
جستجو محدود و نمونه‌ای است، نه پیمایش کامل اینترنت؛ نتایج قدیمی و آگهی‌های
بسته نیز باید در بررسی بعدی کنار گذاشته شوند.

ماژول‌های جدید: web_search، web_fetch، job_parser و discovery؛
discover_jobs.py فقط نقطهٔ ورود است. تست‌ها بدون شبکه اجرا می‌شوند؛
اجرای واقعی با کلید Brave و مدل کاربر هنوز تست نشده است.
