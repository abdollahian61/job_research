# تنظیم منابع جستجو

فایل `sources.json` محل تغییر وایت‌لیست است. آدرس و فعال بودن منابع را
اینجا عوض کنید؛ برای این تغییرات نیازی به دستکاری منطق اصلی برنامه نیست.

منابع اولیه: Relocate.me برای فرصت‌های ریلوکیشن؛ LinkedIn و Welcome to the
Jungle برای کشف فرصت‌های فنی؛ GulfTalent و Bayt برای منطقهٔ خلیج فارس؛
Federal Employment Agency برای آلمان. هیچ‌یک تضمین ارائهٔ ویزا یا انتشار
ایمیل HR نیستند. شواهد هر آگهی باید جدا بررسی شود.

## افزودن سایت

یک شیء مشابه موارد موجود به آرایهٔ sources اضافه کنید:
```json
{
  "id": "another_board",
  "name": "Another job board",
  "url": "https://jobs.example.com/",
  "enabled": true,
  "allow_subdomains": false,
  "purpose": "job_discovery",
  "adapter": "pending",
  "notes": ""
}
```

این مثال آدرس واقعی نیست. شناسه باید یکتا باشد. برای توقف یک منبع enabled
را false کنید. allow_subdomains را تنها زمانی true کنید که زیردامنه‌ها نیز
مجاز باشند. تغییرات را بررسی کنید:

```bash
python source_config.py
```

افزودن آدرس، آن دامنه را به فهرست مجاز اضافه می‌کند؛ به‌تنهایی استخراج از
هر سایت دلخواه را پیاده نمی‌کند. منابع فعلی adapter=pending دارند و
جمع‌آوری هنوز فعال نیست. سایت‌های دارای ساختار/API متفاوت ممکن است adapter
اختصاصی بخواهند. هنگام پیاده‌سازی crawler باید لینک‌ها و هر redirect
پیش از درخواست با همین وایت‌لیست بررسی شوند.

## صفحات رسمی شرکت و ایمیل استخدام

بعد از پیدا کردن شرکت، صفحهٔ استخدام رسمی آن را به company_sources با
همان ساختار اضافه کنید؛ دامنهٔ جدید به‌صورت خودکار مجاز نمی‌شود.

اولویت مخاطب:
1. ایمیل استخدامی منتشرشده برای همان موقعیت.
2. ایمیل استخدام در صفحهٔ رسمی شرکت.
3. مخاطب رسمی آژانس استخدام که همان موقعیت را نمایندگی می‌کند.

همراه هر ایمیل، لینک منبع و ارتباط آن با استخدام ثبت شود. وجود عبارت HR در
نام یا معتبر بودن قالب ایمیل کافی نیست. ایمیل پشتیبانی/فروش/رسانه یا آدرس
حدسی استفاده نشود. اگر مسیر رسمی درخواست فرم ATS باشد، لینک همان فرم
ثبت می‌شود؛ نبود ایمیل با ساختن آدرس جبران نمی‌شود.

contact_policy قواعد بالا را در تنظیمات ثبت می‌کند. اجرای استخراج و
کنترل ارسال هنوز پیاده نشده است.
